# HealthBridge — Patient journeys and hospital history

The updated local HealthBridge installation adds longitudinal care-episode tracking while retaining the existing MRI, UPI QR payment, three-portal sign-in and other features.

## New records

- 18 additional patient profiles across arrival, active admission, ICU and discharge stages (24 profiles in a fresh installation).
- Six additional doctor accounts, including specialties. The original doctor/admin/patient accounts are unchanged.
- 18 current appointments with dates and time slots, 18 earlier completed appointments, current and earlier consultation/report records, prescriptions and billing entries.
- 24 connected care episodes spanning the original six patients and the additional profiles, with timestamped history and medication timing labels.
- Shared care-episode updates visible to authorized accounts in **Care log** and **Health journey**.

Clinical details are **illustrative training records**. Do not import them into a live patient environment or treat a demonstration document or MRI output as an authenticated clinical result.

## The three care-log workflows

**Arrival / check-in:** A patient can record an arrival with the reason for visit. Arrival time is generated by the server. Authorized doctors and staff can view and update the episode.

**Hospital / ICU:** Doctors and staff can update the visit stage, department, bed and ward, medication timetable, and notes. Existing invoice data appears alongside the admission record.

**Discharge / follow-up:** The record retains earlier visits, lab reports, prescriptions, inpatient activity, discharge time and invoice status. Unpaid bills remain unpaid until settled through a verified hospital workflow.

## Run on Windows with VS Code

Open PowerShell and run from Downloads:

```powershell
cd "$HOME\Downloads\HealthBridge-Care-Journey-Updated\HealthBridge-Updated"
npm install
```

In terminal 1 (optional experimental MRI service):

```powershell
python -m pip install -r inference\requirements.txt
python inference\server.py
```

In terminal 2:

```powershell
$env:MRI_API_URL="http://127.0.0.1:8001"
$env:HB_UPI_ID="hospital-verified-upi@bank"
$env:HB_UPI_NAME="HealthBridge Hospital"
npm run dev
```

Open http://localhost:5173. Set the real authorized hospital UPI ID before allowing a payment request. Do not send money to the placeholder.

## Existing database / upgrades

New training records are added once by the `care-journey-v1` migration marker. Existing patient and account data remain in place. **Do not delete the `local-data` folder** to get the new content; it contains the current local database.

The extra content and care-episode API are implemented for the local Node.js development server (`npm run dev`). Cloud-hosted deployment requires implementing equivalent persistence and authorization on the hosted backend before use.

## Model notes

EfficientNet-B0 includes an experimental MRI checkpoint. DenseNet121 remains an ImageNet pretrained backbone and is not an Alzheimer's diagnostic model. This release does not add invented MRI diagnoses, accuracy statistics or clinically validated stage predictions.
